# #49 Firebase 세션 생성·참가자 준비 상태 연동

## 구현 범위

- `AppContainer`에서 실제 Session/Member Repository를 주입한다.
- 선택한 등록 도면의 `FloorPlanReference`, 정리한 훈련명, `waiting` 상태로 세션을 생성한다. 선행 0을 허용하는 6자리 PIN을 생성하며 PIN 충돌일 때만 총 5회까지 시도한다.
- 저장 성공 후 팀 준비 화면으로 이동하고 실제 PIN을 표시한다. 참가자 목록은 현재 세션의 스냅샷으로 교체하며 빈 목록, 참가, 준비 변경을 반영한다.
- 제품 흐름의 Mock 참가자·샘플 선택을 제거하고 Preview Fixture로 분리했다.
- 화면 이탈 시 구독을 취소한다. 준비 화면의 뒤로가기는 서버 종료와 PIN 회수가 성공한 뒤 화면을 이동한다.
- 공통 모델·Repository 프로토콜·저장 경로는 변경하지 않았다.

## 리뷰 경계 조건 수정

`MemberConnectionState`는 교관 Store 내부의 `idle / connecting / connected / failed` 상태다. 훈련 시작은 준비 화면, 유효한 현재 세션, 종료 중이 아님, 현재 구독의 스냅샷 수신을 모두 만족해야 한다.

1. 세션 종료 중에는 UI뿐 아니라 두 시작 메서드, 재연결, 중복 뒤로가기도 차단한다.
2. 구독 실패 후 이전 참가자 목록은 유지하되 시작 근거로 사용하지 않는다. 재연결 첫 스냅샷 전에는 연결 중으로 표시하며 시작을 차단한다.
3. 종료 실패 시 다시 구독하고 새 스냅샷을 받은 뒤에만 시작을 허용한다. 스트림이 예기치 않게 정상 종료된 경우에도 재연결할 수 있다.

## 자동 검증

- `bash scripts/check-instructor-store.sh`: 통과. PIN 충돌·일반 오류·수동 재시도, 빈 스냅샷, 실제 이름·준비 반영, 오류·재연결 대기 중 두 시작 경로 차단, 전원/일부 준비 복구, 종료 지연·중복 요청·실패 복구, 구독 취소·늦은 스냅샷 무시를 검사한다.
- `CQB_FIREBASE_EMULATOR_TESTS=1 swift test --package-path CQB/Packages/CQBCore`: 42개 통과, 건너뜀 없음. 세션/대원/PIN 회수는 REST 계약·규칙 검사이며 실제 앱 SDK 검증을 대체하지 않는다.
- InstructorApp Debug 시뮬레이터 빌드 통과.
- MemberApp Debug/Release 빌드와 Release 바이너리의 테스트 스위치 제외 확인은 앞선 준비 상태 검증에서 통과했다.

## 실제 앱 검증

2026-10-12, iPad Pro 13-inch (M5) / iPhone 18 Pro, iOS 27 시뮬레이터와 로컬 Auth·Firestore·Storage 에뮬레이터를 사용했다.

- 앞선 세션 PIN `121094`에서 실제 앱의 세션/PIN 저장, 대원 `딕슨` 참가, 테스트 스위치의 준비 완료·해제와 교관 `1/1 ↔ 0/1` 실시간 반영을 확인했다.
- 수정 앱에서는 도면을 새로 등록해 세션 `B55B4354-C6C3-4CE2-B54E-34423965B2B4`, PIN `220822`를 실제 SDK로 생성했다. 빈 목록·시작 비활성화를 확인했다.
- 대원 `딕슨`이 새 PIN으로 참가하고 좌표를 고정한 뒤, MemberApp 테스트 스위치로 보낸 준비 완료가 교관 앱에 `1/1`로 반영됐다.
- 구독 오류는 새 테스트 세션의 `instructorUid`만 임시 변경해 재현했다. 실제 SDK 로그의 `FIRFirestoreErrorDomain code=7`과 교관 앱의 연결 끊김·재연결 버튼을 확인했다. 기존 `1/1` 목록이 남아 있어도 훈련 시작은 비활성화됐다. 보안 규칙이나 운영 데이터는 변경하지 않았고, 테스트 소유자는 원래 값으로 복구했다.
- 오류 중 MemberApp에서 준비 완료를 해제하고, 소유자 복구 후 교관 앱의 **다시 연결**을 눌렀다. 최신 스냅샷으로 `0/1`이 표시됐고, MemberApp에서 다시 준비 완료로 바꾸자 추가 재연결 없이 `1/1`과 시작 버튼 활성화가 돌아왔다.
- 13:08 KST에 교관 준비 화면에서 **뒤로**를 눌러 세션 생성 화면으로 돌아왔다. Firestore의 해당 세션은 `status: ended`였으며, `pins/220822` 조회는 `404 NOT_FOUND`였다. MemberApp도 “훈련이 시작되기 전에 세션이 종료되었습니다.”를 표시하고 참가 화면으로 돌아왔다.
- 같은 PIN `220822`로 MemberApp에서 재참가하면 “PIN을 확인해주세요.” 오류가 발생해 회수된 PIN으로 참가할 수 없음을 확인했다. 테스트 세션 문서는 검증 기록으로 남고 PIN은 회수된 상태다. 기존 세션 `121094`는 변경하지 않았다.

## 제한과 후속 범위

- 시뮬레이터는 AR 추적을 지원하지 않는다. MemberApp의 테스트 스위치는 Debug + 시뮬레이터 + 에뮬레이터 연결에서 서버 준비 보고만 대체하며, AR·녹화 시작 조건을 우회하지 않는다. 사용법은 [공통 에뮬레이터 문서](../../../docs/firebase-emulator.md)를 따른다.
- 실기기의 실제 AR·녹화는 이 검증에 포함하지 않는다.
- 훈련 시작·종료 버튼의 서버 `running`·`ended` 전송, 기록/AAR 준비 판단, 앱 강제 종료 후 세션 복구는 이슈의 명시적 제외 범위다.
