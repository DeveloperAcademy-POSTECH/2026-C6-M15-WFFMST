# Issue #111 이동 불가 영역 보수적 후처리 비교

## 목적

Core ML 벽 마스크에서 작은 고립 영역과 작은 내부 구멍을 제한적으로 정리하고, 긴
가로·세로 벽 끝점을 정렬했을 때 사용자 편집량이 줄어드는지 확인한다. 이 실험은 앱의
기본 추론 경로 또는 `resolved-mask.bin` 계약을 변경하지 않는다.

## 구현

`LocalWallMaskPostprocessor`는 다음 세 처리를 독립적인 파라미터로 제공한다.

1. 경계에 닿지 않은 작은 blocked 연결 요소 제거
2. 경계의 외부 공간과 연결되지 않은 작은 free 구멍 채우기
3. 충분히 긴 가로·세로 run이 연속된 벽 띠의 끝점 중앙값 정렬

blocked 요소는 8방향, free 구멍은 4방향 연결을 사용한다. 직선 정렬은 끝점 차이가
설정 거리 이내일 때만 수행하고, 수직 방향 지지가 있는 셀은 코너·교차점으로 간주해
삭제하지 않는다. 모든 처리의 총 변경량은 격자 셀 비율로 제한한다.

## 비교 조건

- 입력: 일반 아파트 3장, 도서관 4·5층, C5 5층, 함선 도면
- 격자: 앱과 동일한 2px top-left row-major blocked 격자
- 공통 변경 상한: 전체 격자의 0.5%
- 결과물: 원본, Core ML 원본 마스크, 후처리 마스크, 추가·삭제 diff, JSON 지표

| 설정 | 요소 제거/구멍 채우기 | 직선 정렬 | 변경률 중앙값 | 변경률 범위 | 제거 셀 | 추가 셀 | 후처리 중앙값 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| Light | 4셀 미만 / 4셀 이하 | 없음 | 0.012% | 0.005~0.028% | 310 | 108 | 2.90ms |
| Conservative | 8셀 미만 / 8셀 이하 | 없음 | 0.033% | 0.013~0.062% | 757 | 222 | 2.86ms |
| Strong | 16셀 미만 / 16셀 이하 | 없음 | 0.068% | 0.030~0.088% | 1,386 | 318 | 2.78ms |
| Axis experiment | 8셀 미만 / 8셀 이하 | 길이 24, 두께 12, 이동 2셀 | 0.052% | 0.028~0.063% | 757 + 204 | 222 + 186 | 3.82ms |

시간은 개발 Mac의 1회 실행값이며 실기기 성능을 대표하지 않는다. 정답 마스크가 없는
실제 도면 비교이므로 변경 셀 수는 정확도 지표가 아니다.

## 정성 결과

- 일반 아파트에서는 Conservative 설정이 주요 벽과 문 개구부를 유지하면서 고립된 점과
  작은 내부 구멍만 정리했다.
- Strong 설정은 변화량은 여전히 작지만 도서관과 함선에서 실제일 수 있는 얇고 분리된
  선까지 제거할 위험이 증가했다.
- 함선의 곡선·사선은 직선 정렬 대상에서 제외되어 유지됐다.
- Axis experiment는 7개 도면에서 184개 벽 띠를 정렬했지만 추가 186셀, 삭제 204셀에
  그쳐 전체 모양의 시각적 개선은 작았다.
- 현재 끝점 정렬만으로 Core ML 마스크를 눈에 띄게 반듯한 벽으로 바꾸기는 어렵다.
  윤곽선 또는 중심선 기반의 더 강한 벡터화는 문 폐쇄와 곡선 손상 위험이 있으므로 별도
  실험과 정답 기준이 필요하다.

## 결론

후속 적용 후보는 `Conservative` 설정이다. 처리 시간이 약 3ms이고 주요 구조 손상이
관찰되지 않았지만, 정답 마스크 없이 사용자 수정량 감소를 증명할 수 없으므로 이번
이슈에서는 앱 기본 동작에 연결하지 않는다.

직선 정렬은 안전 조건을 만족하지만 효과가 작아 적용을 권장하지 않는다. 실제 적용은
Core ML+외곽 통합 결과에서 사용자 편집 횟수를 측정한 뒤 별도 기능 이슈로 결정한다.
