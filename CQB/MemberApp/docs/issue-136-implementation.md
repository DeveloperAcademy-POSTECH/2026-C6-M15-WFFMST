## 구현 및 이슈 할 일 대조

- 최신 색상·타이포그래피·간격·반경·그림자 토큰과 공통 `.dsPrimary`, `.dsSecondary`, `.ds` 입력 스타일을 사용한다. #129의 SetupStatusRow와 UploadProgressView를 재사용한다.
- 안내 카드와 Figma 뒤로가기 SVG는 MemberApp 내부에 둔다. 도면은 실제 세션 이미지이며 선택 마커는 입력 좌표로 그린다.
- 참가 화면: 세로 폼 / 가로 병렬 폼, PIN 숫자 6자리 제한, 이름 공백 정리, 참가 활성화 조건을 유지한다. 키보드 이전·다음·완료와 스크롤을 제공한다. 접근성 글자 크기에서는 가로에서도 폼을 세로로 쌓는다.
- 위치 설정: 가로에서는 좌우 container Safe Area를 무시해 도면·패널을 화면 양 끝까지 배치한다. 세로 및 상하 Safe Area는 유지한다. 패널 위치를 방향에 따라 변경하고, 기존 정규화 좌표·확대·이동·재선택 및 두 점 선택 조건을 유지한다. `훈련 시작`은 기존 확인 callback을 호출해 대기로 이동한다. 직접 녹화를 시작하지 않는다.
- 대기·기록: 제목·안내·타이머를 새 디자인으로 변경한다. 카메라 준비·오류·추적·오디오 경고를 화면에서 표시하고 재준비·위치 재설정·녹화 재시도·직접 종료 경로를 유지한다.
- 업로드: 세로·가로 배치와 대기·완료 문구를 적용한다. 진행률과 서버 저장 완료 여부를 구분하고, 오류·재시도·전송 종료 확인·홈 활성화 조건을 유지한다.
- 데모 진입·종료와 시뮬레이터 보조 컨트롤을 유지하고 화면 하단 inset으로 배치한다. 저장·보정·진단 화면을 제거하지 않는다.
- 화면별 기본·선택·완료·가로·큰 글자 Preview를 추가했다. Store는 위치 설정 단계의 참가 화면 복귀 허용과 기존 상태 초기화 연결을 변경했다. Repository·Firebase·공통 모델 및 저장 계약은 변경하지 않았다.
- 방향 허용 범위는 일반 화면에서 `.allButUpsideDown`, TrainingRecordingView에서 `.landscape`이다. 가로 고정 화면을 떠날 때 실제 기기 방향을 다시 요청한다. 얼굴 위·아래 등 방향을 결정할 수 없는 경우 임의로 세로를 강제하지 않는다.

## 디자인과 실제 기능의 차이 및 후속 작업

1. **운영 모드 뒤로가기:** 위치 설정 단계에서 `returnToJoin()`을 허용하고 기존 초기화 경로로 세션 구독·준비 상태 보고·카메라·좌표·참가 정보를 정리한 뒤 참가 화면으로 복귀한다. 데모에서는 기존 데모 종료를 호출한다. 서버 참가 문서를 삭제하는 API는 없어 서버 문서는 유지되며 heartbeat 갱신만 중단된다. 서버 목록에서 즉시 제거하는 기능은 별도 데이터 계약 논의가 필요하다.
2. **WorldMap 스캔·재위치 인식:** `isReady`는 추적 준비 상태이며 스캔 완료가 아니다. Figma의 스캔 중·준비 완료는 `추적 준비 중`·`준비 완료`로 대응하고 안내에도 추적 준비라고 명시했다. 실제 스캔 진행률·인식 실패·수동 전환 상태 추가는 별도 기능 이슈가 필요하다. 아직 별도 GitHub 이슈를 생성하지 않았다.
3. **공통 스타일 #128 의존성:** 공통 Primary의 비활성 배경은 현재 gray800으로 위치 패널과 같다(Figma gray600). 포커스 입력 테두리·tint도 현재 공통 스타일을 따른다(Figma 흰색과 차이). #128에서 공통 스타일을 수정하면 반영된다. 이번 화면 변경에서 패키지를 중복 구현하지 않았다.
4. **#129 재사용:** 업로드 바는 기존 공통화된 8pt 캡슐을 유지한다. 일부 Figma 가로 시안의 13pt 직사각형과 차이가 있다.

## 검증 결과 — 2026-11-02

- MemberApp 시뮬레이터 빌드 성공: Xcode 27.0, iPhone 17 / iOS 27.0.
- MemberApp iOS 기기 대상 코드 서명 없는 빌드 성공. 실기기 설치·실행 결과는 아니다.
- 관련 회귀 테스트 21개 중 20개 통과: 방향 5개, 데모 시나리오 5개, 데모 완료 2개, 녹화 시작 수명주기 8개.
- 기존 MemberUploadFailureTests 1개 실패: 테스트 준비 중 `video-chunks` 상위 폴더가 없어 파일 쓰기가 실패한다. 업로드 로직 실행 전 실패이며 이번 UI 변경에서 수정하지 않았다.
- 실제 View 소스를 사용하는 임시 시뮬레이터 UI 확인 앱에서 PIN·이름 입력/완료, 참가 callback, 도면 출발점 선택, 대기 UI를 확인했다. 기기를 세로로 돌려도 대기는 가로 유지, 위치 재설정으로 나가면 세로 복원되는 것을 확인했다.
- 같은 임시 앱에서 업로드 실패 → 재시도 callback → 80% → 완료 100% → 홈 버튼 활성화를 확인했다. 카메라·네트워크는 대체 구현이므로 실제 AR·서버 업로드 검증으로 보지 않는다. 임시 앱 소스는 저장소에 포함하지 않는다.
- 서로 다른 크기(402×874, 874×402, 320×568)와 접근성 글자 크기 렌더링을 검토했다. 실기기 키보드, 도면 확대 제스처, 모든 큰 글자 스크롤 경로는 추가 확인이 필요하다.

- [ ] 실제 앱 데모 진입·종료와 보조 컨트롤을 포함한 전체 흐름 수동 확인.
