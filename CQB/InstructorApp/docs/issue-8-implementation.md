- 실제 Apple Pencil 입력, 두 손가락 확대·이동 제스처의 충돌 및 체감 성능은 실기기 확인 필요. 시뮬레이터 마우스 입력 검증과 구분한다.

- 공통 도면 계약이 아직 없으므로 앱 내부 임시 타입으로 연결했다. 선행 데이터 계약 완료 조건은 충족된 것으로 간주하지 않는다. 계약 PR 이후 공통 타입·서비스 연결은 별도 작업이다.
- 모든 등록 결과는 메모리에만 존재한다. Firebase 요청, 파일 영속 저장, 앱 재실행 복원, 상세/수정/삭제는 구현하지 않는다.
- Issue의 체크박스와 PR은 자동으로 수정하지 않는다. 실기기 입력 검증과 선행 계약 상태를 확인한 뒤 완료 판단한다.

## 실기기 파일 재선택 멈춤 대응

- 관측: 파일 선택창 표시 중 메인 스레드가 키보드/responder 경로에서 SwiftUI 잠금을 기다리고, AsyncRenderer도 CALayer 잠금을 기다렸다. 재개 후 재채집에서도 동일했다. 잠금 소유 관계는 확인하지 못했으므로 시스템 교착의 정확한 원인을 확정한 것은 아니다.
- 입력 조정은 화면 수명의 `FloorPlanImportPresentation`에 둔다. Store나 공통 계약에 UIKit 포커스/선택창 상태를 추가하지 않는다.
- 진행 중인 획은 중단하지 않는다. 획 종료 후 캔버스 입력을 잠시 중지하고 입력 포커스를 해제한다. 키보드가 표시 중이면 didHide를 기다리고 다음 main queue 작업에서 선택창을 연다.
- 키보드 알림이 오지 않으면 2초 후 준비 상태를 해제하고 재시도를 안내한다. 시간 경과만으로 선택창을 강제로 띄우지 않는다.
- 중복 요청, 준비 취소, 화면 이탈 후 지연된 콜백을 차단한다. 선택 취소는 도면/편집/외곽/축척을 지우지 않으며 취소 오류를 실패로 표시하지 않는다.
- 캔버스 도구/굵기가 바뀌지 않으면 PKInkingTool을 다시 설정하지 않는다.
- 자동 테스트: 키보드 종료 순서, 중복/지연 요청, 준비 timeout, UITextField first responder 해제, 진행 중 획 차단, 취소 후 편집 재개와 draft 보존을 추가했다. 기존 5개 검증 스크립트 모두 통과.
- 빌드: generic iOS Simulator 및 generic iOS 타깃 모두 성공. 실기기 타깃은 `CODE_SIGNING_ALLOWED=NO`로 컴파일만 확인했으며 연결된 실기기에 새 앱을 설치하지 않았다.
- 시뮬레이터: 이름 입력 → 실제 파일 선택, 막기 → 재선택창 → 취소 → 열기 편집 → 파일 재선택까지 확인. 마지막 재선택은 동일한 PNG를 다시 골라 새 import가 시작되는 경로로 검증했다.
- 남은 검증: 문제를 재현한 유선 연결 실기기에서 수정 빌드를 실행하고, 소프트웨어 키보드 표시/숨김 및 Pencil/손가락별로 위 흐름을 반복해야 한다. 시뮬레이터 통과만으로 실기기 교착 해결을 확정하지 않는다.

## 붓 종료 시 표시 안정화 / 레이어 조절

- 크기 변화 원인: 편집 결과 계산 중 표시되는 안내가 바깥 VStack의 높이를 차지해 캔버스가 작아지고 최소 fit zoom이 다시 계산됐다. 처리·오류·파일 선택 준비 안내를 캔버스 overlay로 이동해 표시 여부가 캔버스 크기를 바꾸지 않게 했다.
- 깜빡임 유발 경로: 획 재계산을 시작할 때 마스크 이미지를 비워 원본만 잠깐 표시했다. 같은 이미지의 획 추가/되돌리기/초기화는 직전 마스크를 유지하고 새 결과가 준비되면 교체한다. 원본 자체를 흑백 변환하는 경로는 발견하지 못했으며, 실기기에서 보고된 색 변화가 전부 해결됐는지는 재확인이 필요하다.
- 표시 유지와 등록 유효성은 분리한다. 획 재계산 시작 즉시 resolvedGrid를 무효화해 등록을 막는다. 외곽 변경과 명시적 재시도는 이전 마스크를 지운다. 이미지 교체는 이후 코드 리뷰 보완으로 성공 시에만 교체하고 실패·취소 시 기존 마스크를 유지하도록 변경했다.
- PoC를 참고해 원본/장애물 농도, 장애물 표시 토글, 보라·청록·검정·빨강 선택 및 겹쳐 보기/마스크만/도면만 프리셋을 추가했다. 설정은 화면의 로컬 상태이며 도면·격자·등록 데이터와 공통 계약을 바꾸지 않는다.
- 자동 검증: 5개 검증 스크립트 모두 통과. 직전 마스크 유지 중 등록 차단, 새 결과 교체, 원본 이미지 불변, 독립 레이어 농도/색/표시, fit·확대 상태 유지 및 실제 FloorPlanCreateView의 처리 전후 캔버스 크기·zoom 불변 테스트를 추가했다.
- 시뮬레이터 가로 화면: 실제 PNG 입력 후 마스크만/도면만/겹쳐 보기와 청록 선택을 확인했고, 해당 설정에서 막기 획을 추가해 결과 반영을 확인했다. 순간적인 실기기 깜빡임을 프레임 단위로 검증한 것은 아니다.
- generic iOS Simulator 및 generic iOS 빌드 성공. 실기기 빌드는 서명 없이 컴파일만 확인했으며 실기기 설치·Apple Pencil 재검증은 남아 있다.

### 붓 편집 중 일시적 UI 표시 최소화

- 직전 마스크를 유지하는 획 재계산은 진행 표시/취소 안내를 띄우지 않는다. 최초 이미지 추출, 외곽 변경, 명시적 재시도의 진행 표시와 모든 오류 안내는 유지한다. 실제 계산 및 등록 차단은 제거하지 않는다.
- 파일 선택과 편집 도구 버튼은 붓 입력/획 재계산 동안 disabled 의미와 입력 차단을 유지하되 색상만 유지한다. 획 없음·외곽 점 부족 등 지속적인 비활성 조건은 기존처럼 구분한다. 단계 이동 버튼은 등록 조건에 따른 비활성 표시를 유지한다.
- 표시 전용 레이어 컨트롤은 붓 입력 중에도 사용할 수 있다. 격자나 진행 중인 획에는 영향을 주지 않는다.
- 갤러리 입력은 이번 수정에서 추가하지 않았다. 현재 선택기 및 서비스는 PNG/JPEG만 허용하며, 두 형식은 방향 보정·4096px 제한·흰 배경 합성 후 PNG/RGBA로 정규화되어 같은 추출/편집/축척 로직을 사용한다. HEIC/HEIF 등의 입력 지원은 선택 경로와 서비스 검증을 함께 보완해야 한다.
- 검증: 등록 상태·이미지 가져오기·UIKit/SwiftUI 캔버스 테스트 통과. 버튼 스타일을 UIHostingController로 렌더링해 정상/일시 비활성 상태의 PNG가 같고 지속 비활성 상태와는 다른 것을 확인했다. Simulator 빌드 통과. 실제 Pencil 입력의 체감 확인은 실기기 재검증이 필요하다.

## 코드 리뷰 후 보완

- 파일 교체는 정규화·추출·첫 격자/미리보기 생성이 모두 성공한 뒤 한 번에 반영한다. 처리 중에는 기존 이미지·획·외곽·축척·확인 상태를 보유하고 등록을 막는다. 실패/취소 시 기존 draft를 유지하며, 늦게 도착한 이전 요청 결과는 generation 검사로 무시한다. 성공 시에만 기존 편집을 초기화한다.
- 교체 중에도 이전 마스크가 존재하므로 `isImporting`으로 획 재계산과 구분한다. 이미지 교체의 진행/취소 표시는 유지하고 편집 컨트롤은 잠근다.
- 이미지별 `LocalFloorPlanReplayCache`는 외곽 적용 전 편집 격자와 외곽 판정 마스크를 보관한다. 추가된 획만 적용하며, undo/reset/이력 교체 시 base부터 재생한다. 외곽이 바뀐 경우에만 외곽 판정을 다시 한다. 전체 격자를 획마다 따로 보관하지 않으며 이미지 교체 성공·draft 초기화 시 캐시를 해제한다.
- 계산은 캐시의 값 복사본에서 수행하고, 취소되지 않은 최신 요청이 성공했을 때만 Store에 결과/캐시를 함께 반영한다. 화면·최종 등록의 격자 의미와 PNG 파일 형식은 변경하지 않는다. PNG 생성 자체는 여전히 매 계산마다 수행한다.
- 캔버스는 이미지/뷰 크기가 달라질 때만 fit 레이아웃을 갱신하고, 마커 입력 또는 실제 줌 배율이 달라질 때만 다시 그린다. 동일 입력과 레이어 농도/색상만의 변경은 캔버스 레이아웃·마커를 무효화하지 않는다.
- 회귀 검증: 교체 실패/취소/성공, 이전 요청의 늦은 성공, 빠른 연속 획과 계산 취소 후 재시도, 홀수 크기·겹치는 획·undo/reset·외곽 변경/해제에 대한 캐시/전체 계산의 셀 일치를 확인했다. UIHostingController에서 교체 실패 후 이미지 객체와 확대 상태 보존, UIKit에서 무변경/농도 변경 시 불필요한 무효화가 없는 것도 검증한다.
- 성능 참고: Mac `swiftc -O`, 4096×4096 이미지·외곽 256점에서 캐시 준비 후 다음 획 반영을 비교했다. 전체 계산+PNG 약 0.874초, 증분 계산+PNG 약 0.024초였으며 격자 및 PNG가 일치했다. 단일 조건의 측정이고 실제 iPad 성능 보장은 아니다. 외곽 변경·undo의 전체 재생, 매우 복잡한 단일 획의 비용은 남는다.
- 공통 데이터 계약/Firebase/디자인 시스템은 변경하지 않았다. 실기기 Apple Pencil 반복 입력과 Instruments 측정은 별도 확인이 필요하다.
