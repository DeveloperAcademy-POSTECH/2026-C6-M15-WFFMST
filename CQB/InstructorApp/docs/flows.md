# InstructorApp 화면 흐름과 상호작용 정책

교관 앱의 현재 MVP 동작을 정리한다. 공통 책임·의존성 규칙은 [공통 아키텍처](../../../docs/architecture.md), 코드 작성 규칙은 [AGENTS.md](../AGENTS.md)를 따른다.

## 도면 등록

도면 목록 → 생성 → 이름 입력·파일 선택 → 이동 불가 영역 확인·편집 → 축척 설정 → 최종 확인·등록 → 도면 목록

- 도면 생성 화면의 뒤로 가기는 도면 목록으로 이동한다. 도면 목록의 뒤로 가기는 홈으로 이동한다.
- 파일 선택은 PNG/JPEG를 지원하며 갤러리 선택이나 서버 업로드가 아니다.
- 자동 추출·바깥 영역 보정 결과는 초안이며 사용자가 이동 불가 영역을 추가하거나 삭제해 검수한다.
- 편집에는 Pencil·한 손가락을, 이동·확대에는 두 손가락을 사용할 수 있다. 이동 도구에서는 한 손가락 이동도 지원한다.
- 파일 교체는 처리 성공 시에만 반영한다. 실패·취소 시 기존 편집을 유지한다.
- 획 재계산 중 직전 미리보기를 유지하고 매 획마다 로딩을 표시하지 않는다. 새 결과가 준비되기 전에는 다음 단계 진행·등록을 막는다.
- 이름·이미지·최종 격자·외곽·축척이 유효하고 최종 확인을 마쳐야 등록할 수 있다.
- 등록한 도면의 목록 정보와 `FloorPlanReference`는 기기에 저장하고 앱 재실행 후 복원한다. 복원한 도면은 세션 생성 화면에서 선택할 수 있다.
- 목록의 상세보기에서는 Storage 파일을 내려받아 원본 이미지와 최종 마스크를 겹쳐 표시하고 이름과 최종 수정 시간을 보여준다.
- 도면 수정은 현재 최종 마스크를 기준으로 이동 불가·가능 영역만 편집한다. 이름·원본 이미지·축척은 유지한다.
- 수정본은 기존 Storage 파일을 덮어쓰지 않고 새 `floorPlanID`로 올린 뒤 같은 로컬 카탈로그 항목의 참조와 최종 수정 시간을 교체한다.
- 도면 삭제는 로컬 카탈로그에서만 제거한다. 과거 세션의 참조를 보존하기 위해 Storage 파일은 즉시 삭제하지 않는다.
- 사용하지 않는 과거 Storage 파일 정리, 다른 기기와의 목록 동기화와 동선 보정은 현재 구현 범위에 포함하지 않는다.

처리 정책의 수치와 검증 이력은 [Issue #8 구현 기록](issue-8-implementation.md)을 참고한다.

## 팀 준비와 훈련 시작

- 선택한 등록 도면의 참조와 훈련명으로 Firebase 세션을 생성한 뒤 실제 6자리 PIN을 표시한다. 생성 중 훈련명·도면 변경, 중복 요청과 뒤로가기를 차단하며, 실패 시 같은 화면에서 입력을 수정하고 재시도할 수 있다.
- 대원 이름·준비 상태는 현재 세션의 참가자 스냅샷으로 표시한다. 빈 목록에는 참가 대기 안내를 표시한다.
- 최초 연결·재연결의 첫 스냅샷 대기 중이거나 구독이 끊긴 동안에는 이전 목록이 남아 있어도 훈련을 시작할 수 없다. 오류 시 `다시 연결`로 현재 목록을 다시 받는다.
- 준비 화면의 뒤로가기는 세션을 `ended`로 변경하고 PIN을 회수한 뒤 생성 화면으로 돌아간다. 종료 중에는 시작·재연결·중복 뒤로가기를 차단한다. 종료 실패 시 오류를 표시하고 참가자 구독을 복구한다.
- 준비 완료 대원이 한 명도 없으면 훈련을 시작할 수 없다.
- 미준비 대원이 일부 있으면 훈련 시작 시 확인을 거쳐 미준비 대원을 현재 세션에서 일괄 제외한다.
- 확인을 취소하면 팀 준비 화면을 유지한다.

## 훈련 진행과 결과 준비

- 훈련 시작은 세션 상태를 `running`으로 저장한 뒤에만 훈련 중 화면으로 전환한다. 요청 중에는 중복 시작과 뒤로가기를 막고, 실패하면 팀 준비 화면에서 참가자 구독을 다시 연결해 재시도한다.
- 훈련 경과 시간은 버튼을 누른 로컬 시각이 아니라 Firestore에서 다시 받은 `Session.startedAt`을 기준으로 1초마다 표시한다. 세션 구독이 끊기면 마지막 서버 시각을 보존하고 재연결할 수 있다.
- 훈련 종료는 세션 상태를 `ended`로 저장한 뒤 결과 준비 화면으로 전환한다. 종료 요청이 실패하면 훈련 중 화면과 타이머를 유지하고 같은 버튼으로 다시 시도한다.
- 결과 준비 화면은 훈련 시작 성공 시 확정한 참가자별 기록을 `수신 대기 / 녹화 중 / 처리·업로드 중 / 완료 / 실패`로 표시한다.
- 완료된 기록이 한 건 이상 있고 확정 참가자 전원이 `done` 또는 `failed`가 되면 자동으로 AAR로 이동한다. `failed` 기록은 AAR 재생 대상에서 제외한다.
- `waiting`, `recording`, `finishing` 상태가 계속되는 대원은 교관이 확인 후 이번 AAR에서 제외할 수 있다. 제외되지 않은 미종결 대원이 없고 완료된 기록이 한 건 이상이면 완료 대원만으로 AAR을 시작할 수 있다.
- 완료된 기록이 한 건도 없으면 전원 실패 또는 전원 제외 상태여도 AAR에 진입하지 않는다.
- AAR 진입 시 완료 대원 목록을 고정하며, 제외했던 대원이 이후 늦게 `done`으로 변경되어도 진행 중인 AAR 대상에는 추가하지 않는다.
- 기록 구독이 끊기면 마지막 상태를 보존하고 자동 진입을 막는다. `다시 연결` 후 첫 최신 스냅샷을 받아 다시 완료 여부를 판단한다.
- MemberApp은 업로드 재시도를 포기할 때 확인을 거쳐 기록을 `failed`로 종결한다. 이 상태 저장이 실패하면 홈 이동을 허용하지 않고 다시 시도할 수 있도록 한다.

## AAR

- 동선과 영상은 같은 대원 선택값을 사용한다.
- 5명 이상 선택된 상태에서 영상 전환을 요청하면 전환하지 않고 최대 4명 제한을 안내한다.
- 모드 전환을 위해 선택값을 임의로 줄이지 않는다.
- `failed`로 종결된 참가자가 있으면 AAR 상단에 기록 자료가 없을 수 있다는 안내를 표시한다.
