# #87 MemberApp 데모 실행 환경과 훈련 시작 흐름

## 구현 범위

- 참가 화면의 `데모 모드 시작` 버튼으로 TestFlight 심사용 데모에 진입한다.
- 데모 중에는 상단 배너와 종료 버튼을 표시한다.
- PIN 입력, Firebase 세션 조회 및 별도 InstructorApp 없이 고정된 로컬 세션에 참가한다.
- 앱에 포함된 `TrainingMap` 리소스를 검증해 시작 위치와 방향 설정 화면에 표시한다.
- 기존 카메라·AR 준비 판정은 그대로 사용한다.
- 준비가 완료되면 `데모 훈련 시작` 버튼으로 로컬 세션에 `running` 신호를 보내 실제 녹화를 시작한다.
- 데모 진입점과 저장소는 `#if DEBUG`에 두지 않아 TestFlight Release 빌드에서도 사용할 수 있다.

## 운영 데이터와의 경계

`MemberDemoScenario`는 실행마다 별도의 `MemberStore`와 메모리 세션 저장소를 만든다. 대원 준비 상태, 기록 메타데이터, 영상 조각 및 보정 결과에 사용하는 데모 Repository도 모두 앱 내부 구현이며 `CQBFirebase` 구현을 참조하지 않는다. 데모 Store는 InstructorApp에 준비 상태를 보고할 필요가 없으므로 참가자 readiness heartbeat와 Repository 쓰기도 시작하지 않는다.

운영 `MemberStore`는 `AppContainer`가 별도로 유지한다. 데모를 종료하면 이 운영 Store의 참가 화면으로 돌아가므로 데모 PIN, 도면, 위치 및 세션 상태가 운영 흐름에 전달되지 않는다. 새 데모 실행은 새 식별자와 Store를 만들어 항상 초기 상태에서 시작한다.

## 사용자 흐름

1. 참가 화면에서 `데모 모드 시작`을 누른다.
2. 번들 도면에서 시작 위치와 바라보는 방향을 지정한다.
3. 카메라 미리보기에서 AR 추적이 준비될 때까지 iPhone을 주변 공간으로 향한다.
4. `데모 훈련 시작`을 눌러 로컬 시작 신호를 보낸다.
5. 기존 `ARRecordingService`가 실제 영상·동선 기록을 시작한다.

기록 종료, 데모 파일 분리, 경로 보정, 로컬 업로드 완료 및 정리 정책은 후속 이슈 #88에서 완성한다. 현재 단계에서도 데모에 주입된 Repository는 서버 쓰기를 수행하지 않는다.

## 검증

- `MemberDemoScenarioTests`
  - 데모 재시작 시 새 실행 식별자 생성
  - 번들 지도 로드 및 위치·방향 확정 후 대기 상태 도달
  - 별도 InstructorApp 없이 로컬 훈련 시작 신호 수신
  - 새 데모 환경 생성 시 참가 상태 초기화
  - 세션 조회·생성·상태 변경과 참가자 참가·준비 상태 쓰기 미호출을 Spy로 확인
- 실제 iPhone의 카메라·AR 준비와 녹화 시작은 실기기에서 확인한다.
- MemberApp Debug 및 Release 빌드를 확인한다.

공통 모델, Repository 프로토콜, Firebase 저장 경로와 파일 형식은 변경하지 않았다.
